### Two-Phase Approach

This guide follows a two-phase workflow:

| Phase | Steps | Method | Tool |
|-------|-------|--------|------|
| **Phase 1: Infrastructure** | Sections 1–2 | **Automated** | `deploy-exascale-demo.sh` (Terraform) |
| **Phase 2: Configuration** | Sections 3–6 | **Manual** | OCI Console, SQL Developer Web, Azure Portal |

Phase 1 deploys all Azure resources automatically. Phase 2 configures the OCI-side DNS, OAuth, network ACLs, and encryption keys — these require access to the OCI Console and the Oracle Database SQL Developer Web, so they cannot be automated with Azure Terraform.

## 2. Azure Infrastructure Setup (Automated)

All Azure infrastructure is deployed automatically using the orchestrator script, which wraps Terraform. You do **not** need to create resources manually with `az` CLI commands.

### What Terraform Creates

The orchestrator provisions all of the following in a single run:

| Resource | Description |
|----------|-------------|
| Resource Group | `rg-exascale-<location>-<random>` |
| Virtual Network | With subnets for ADBS, Private Endpoints, NAT Gateway, VMs, Firewall |
| Oracle ADBS | Autonomous Database Serverless with Advanced Networking |
| Azure Key Vault | Standard tier, purge-protection enabled, public access initially on |
| Encryption Keys | RSA (2048/3072/4096) and EC (P-256/P-256K/P-384/P-521) |
| Key Vault Private Endpoint | In the Private Endpoints subnet |
| Private DNS Zone | `privatelink.vaultcore.azure.net` linked to VNet |
| Managed HSM | *(Optional, if `DEPLOY_MANAGED_HSM=true`)* |
| Jumpbox VM | Windows VM for accessing Oracle Database SQL Developer Web |
| Azure Firewall | With policies for outbound traffic control |
| NAT Gateway | For outbound connectivity |
| Log Analytics | *(Optional, if `ENABLE_LOG_ANALYTICS=true`)* |
| Event Hub | *(Optional, if `ENABLE_EVENTHUB_LOGGING=true`)* |

### 2.1 Deploy Infrastructure

```bash
# Fresh deployment with Azure Key Vault
./deploy-exascale-demo.sh -akv

# Fresh deployment with Managed HSM
./deploy-exascale-demo.sh -hsm

# Or use the default (reads DEPLOY_MANAGED_HSM from .env)
./deploy-exascale-demo.sh
```

4. Generate `terraform.tfvars` from `.env`
5. Run `terraform init` → `validate` → `plan` → `apply`
6. Display a deployment summary with resource names and IPs

> **💡 Tip**: Use `--only-terraform` (`-tf`) to create only the plan without applying, for review.

**Important**: The ADBS provisioning creates a VCN in OCI automatically. Note the VCN name for DNS configuration (Section 3).

## 3. OCI DNS Configuration (Manual)

> **⚠️ This step is manual.** OCI DNS cannot be configured through Azure Terraform. You must create the Private DNS Zones and A records in the OCI Console.
>
> You will need the following values from the Terraform output (Section 2.2):
> - `akv_name` — Your Key Vault name (e.g., `exascale-kv-982`)
> - `akv_private_ip_address` — Your Private Endpoint IP (e.g., `10.115.2.4`)
> - If using Managed HSM: `mhsm_uri` — Your HSM URI

### 3.1 Access OCI Console

1. Navigate to Azure Portal → Your ADBS resource
2. Click on **Oracle Database@Azure** link
3. This will redirect you to OCI Console (SSO)
4. Navigate to **Autonomous Databases** → Select your ADBS

### 3.2 Identify the VCN

On the ADBS details page, find:
- **Network Information** section
- **VCN Name**: e.g., `VCN-multicloudnetworklink20250605145841`

> **⚠️ Note**: The VCN name is **auto-generated by Oracle** when you create ADBS. The example above shows the format. Your actual VCN name will be different with a different timestamp.

**SAVE THIS NAME** - You'll need it for DNS configuration.

### 3.3 Configure Private DNS Zones in OCI

#### Navigate to DNS Private Views:

1. OCI Console → **Networking** → **DNS Management**
2. Select **Private Views** (left menu)
3. Find the Private View with **same name as your VCN**
   - Example: `VCN-multicloudnetworklink20250605145841`

#### Create Private DNS Zones (Standard Key Vault):

**Zone 1: privatelink.vaultcore.azure.net**

1. Click on your Private View
2. Click **Create Zone**
3. Fill in:
   - **Zone Name**: `privatelink.vaultcore.azure.net`
   - **Zone Type**: Primary
4. Click **Create Zone**

**Zone 2: vault.azure.net**

1. Click **Create Zone** again
2. Fill in:
   - **Zone Name**: `vault.azure.net`
   - **Zone Type**: Primary
3. Click **Create Zone**

#### Add A Records to Both Zones:

> **⚠️ CRITICAL**: Replace `exascale-kv-982` with YOUR Key Vault name and `10.115.2.4` with YOUR actual Private Endpoint IP.

**For each zone, add an A record:**

1. Click on the zone name
2. Click **Add Record**
3. Fill in:
   - **Name**: `exascale-kv-982` ← Replace with **YOUR** Key Vault name (only the name part, no .vault.azure.net suffix)
   - **Type**: A - IPv4 address
   - **TTL**: 300
   - **Address**: `10.115.2.4` ← Replace with **YOUR** Private Endpoint IP from Section 2.4
4. Click **Submit**

**CRITICAL: Add the same A record to BOTH zones with YOUR actual values**

#### Final Configuration Should Look Like:

```
# Example configuration (replace these values with YOUR actual values):

Private View: VCN-multicloudnetworklink20250605145841  ← YOUR VCN name will be different
├── Private Zone: privatelink.vaultcore.azure.net
│   └── A Record: exascale-kv-982 → 10.115.2.4  ← YOUR Key Vault name and YOUR PE IP
└── Private Zone: vault.azure.net
    └── A Record: exascale-kv-982 → 10.115.2.4  ← YOUR Key Vault name and YOUR PE IP
```

> **⚠️ Note**: All names and IPs above are examples from our test environment. Use YOUR actual values.

### 3.4 Verification

Wait 2-3 minutes for DNS propagation, then test from ADBS (Section 7.1).

## 4. Azure AD and OAuth Configuration (Manual)

### 4.1 Initial ADBS Connection

**Access SQL Developer Web:**

Since ADBS uses Advanced Networking (private access only), you must connect through the **Jumpbox VM** deployed by Terraform.

1. Get the Jumpbox connection info from Terraform outputs:
   ```bash
   cd infra-deployment && terraform output -json useful_info | jq '{vm_fqdn, vm_public_ip_address, vm_admin_username}'
   ```
2. RDP to the Jumpbox VM using the FQDN or public IP
3. From the Jumpbox, open a browser and navigate to:
   - Azure Portal → Your ADBS resource → copy the **Private Endpoint URL**
   - Format: `https://<private-endpoint-url>.oraclecloud.com/ords/sql-developer`
4. Login as **ADMIN** user (password from `ADBS_ADMIN_PASSWORD` in `.env`)

### 4.2 Enable Azure Principal Authentication

```sql
-- Connect as ADMIN user in SQL Developer Web

-- Enable Azure authentication
BEGIN
  DBMS_CLOUD_ADMIN.ENABLE_PRINCIPAL_AUTH(
    provider => 'AZURE',
    params   => JSON_OBJECT('azure_tenantid' VALUE '<YOUR-DIRECTORY-TENANT-ID>'));
END;
/
```

**⚠️ CRITICAL: Use Directory (Tenant) ID, NOT Subscription ID**

Get Tenant ID from: Azure Portal → Azure Active Directory → Overview → Tenant ID

### 4.3 Retrieve Consent URL

```sql
-- Configure SQL*Plus output first
SET LINESIZE 200
COLUMN param_value FORMAT A150

-- Get the consent URL
SELECT param_value 
FROM CLOUD_INTEGRATIONS 
WHERE param_name = 'azure_consent_url';
```

**Example Output:**
```
https://login.microsoftonline.com/cacf72a7-xxxx-xxxx-xxxx-xxxxxxxxxxxx/oauth2/authorize?client_id=...
```

**⚠️ If URL contains "www.login.microsoftonline.com", remove the "www."**

### 4.4 Extract Application (Client) ID

The `client_id` parameter in the consent URL is your Azure AD Application ID.

```sql
-- Extract all Azure configuration
SELECT param_name, param_value 
FROM CLOUD_INTEGRATIONS 
WHERE param_name LIKE 'azure%'
ORDER BY param_name;
```

Look for `azure_app_name` - this is your Application ID.

### 4.5 Complete OAuth Consent

1. **Copy the consent URL** from the SQL output
2. **Open in a browser** with internet access (can be your local machine)
3. **Login** with your Azure AD credentials
4. **Grant permissions** when prompted
5. You should see a success message or redirect

### 4.6 Configure Key Vault Access Policy for ADBS Service Principal

> **Note**: Terraform already created an Access Policy for the **Terraform executor** (your user). This step adds a **separate** Access Policy for the ADBS Service Principal created by `ENABLE_PRINCIPAL_AUTH`.

**Using Azure Portal:**

1. Navigate to your Key Vault (name from `terraform output -json useful_info | jq -r '.akv_name'`)
2. Click **Access policies** (left menu)
3. Click **+ Create**
4. **Permissions**:
   - **Key permissions**: Select **Get**, **List**, **Unwrap Key**, **Wrap Key**, **Sign**, **Verify**
   - **Secret permissions**: None
   - **Certificate permissions**: None
5. Click **Next**
6. **Principal**:
   - Search for your Application ID (from azure_app_name)
   - Or search for: `ADBS_APP_OCID1.AUTONOMOUSDATABASE...`
   - Select it
7. Click **Next**, **Next**, **Create**

**Using Azure CLI:**

```bash
# Get the Object ID of your service principal
APP_ID="<your-application-id-from-azure_app_name>"
OBJECT_ID=$(az ad sp show --id $APP_ID --query id -o tsv)

# Set access policy
az keyvault set-policy \
  --name exascale-kv-982 \
  --object-id $OBJECT_ID \
  --key-permissions get list wrapKey unwrapKey sign verify
```

### 4.7 Verify Authentication

```sql
-- Check cloud principal status
SELECT provider, status, principal_name, created_date
FROM USER_CLOUD_PRINCIPALS
WHERE provider = 'AZURE';
```

**Expected Output:**
```
PROVIDER  STATUS    PRINCIPAL_NAME  CREATED_DATE
--------  --------  -------------   ------------
AZURE     ENABLED   ADMIN           17-FEB-26
```

## 6. Key Vault Integration (Manual)

### 6.1 Test DNS Resolution (Critical Pre-Flight Check)

> **⚠️ Note**: Replace `exascale-kv-982` with your actual Key Vault name from Terraform output (`akv_name`).

```sql
-- Verify DNS resolves to PRIVATE IP
SELECT utl_inaddr.get_host_address('exascale-kv-982.vault.azure.net') FROM dual;
-- Replace 'exascale-kv-982' with YOUR Key Vault name
```

**Expected Output**: Your Private Endpoint IP (e.g., `10.115.2.4`)
**❌ If you see a public IP** (e.g., 104.x.x.x), DNS is NOT configured correctly - go back to Section 3.

> **Example**: If your Private Endpoint IP is `10.115.2.4`, the query should return exactly `10.115.2.4`

### 6.2 Test Connectivity to Key Vault

```sql
SET SERVEROUTPUT ON;
BEGIN
  DECLARE
    req   UTL_HTTP.REQ;
    resp  UTL_HTTP.RESP;
    name  VARCHAR2(256);
    value VARCHAR2(1024);
  BEGIN
    req := UTL_HTTP.BEGIN_REQUEST('https://exascale-kv-982.vault.azure.net/healthstatus');
    UTL_HTTP.SET_HEADER(req, 'User-Agent', 'Mozilla/4.0');
    resp := UTL_HTTP.GET_RESPONSE(req);
    
    DBMS_OUTPUT.PUT_LINE('=== Connection Successful ===');
    DBMS_OUTPUT.PUT_LINE('Status: ' || resp.status_code || ' ' || resp.reason_phrase);
    DBMS_OUTPUT.PUT_LINE('');
    
    FOR i IN 1..UTL_HTTP.GET_HEADER_COUNT(resp) LOOP
      UTL_HTTP.GET_HEADER(resp, i, name, value);
      DBMS_OUTPUT.PUT_LINE(name || ': ' || value);
    END LOOP;
    
    LOOP
      UTL_HTTP.READ_LINE(resp, value, TRUE);
      DBMS_OUTPUT.PUT_LINE(value);
    END LOOP;
    
    UTL_HTTP.END_RESPONSE(resp);
  EXCEPTION
    WHEN UTL_HTTP.END_OF_BODY THEN 
      UTL_HTTP.END_RESPONSE(resp);
    WHEN OTHERS THEN
      DBMS_OUTPUT.PUT_LINE('ERROR: ' || SQLERRM);
      DBMS_OUTPUT.PUT_LINE('DETAILS: ' || UTL_HTTP.GET_DETAILED_SQLERRM);
      RAISE;
  END;
END;
/
```

**Expected Success Output:**
```
=== Connection Successful ===
Status: 200 OK

x-ms-keyvault-network-info: conn_type=PrivateLink;addr=10.115.1.116;...
{"ApplicationHealthState":"Healthy"}
```

**✅ Look for `conn_type=PrivateLink`** - This confirms private endpoint routing!

### 6.3 Configure Customer-Managed Key

> **Note**: Use your Key Vault URI from `terraform output -json useful_info | jq -r '.akv_uri'` and one of the key names created by Terraform (see Section 2.3). For example: `exascale-encryption-rsa-4096`.

**Via OCI Console:**

1. Navigate to your ADBS in OCI Console
2. Click **More Actions** → **Manage customer-managed keys**
3. Configure:
   - **Vault Type**: Azure Key Vault
   - **Vault URI**: Your Key Vault URI (e.g., `https://exascale-kv-982.vault.azure.net/`)
   - **Key Name**: One of the keys from Section 2.3 (e.g., `exascale-encryption-rsa-4096`)
   - **Key Version**: Leave empty (uses latest version automatically)
   - **Cloud Provider**: AZURE
4. Click **Save Changes**

**Via REST API:**

```bash
# Get ADBS OCID from OCI Console
ADBS_OCID="ocid1.autonomousdatabase.oc1.uk-london-1.xxxxxx"

# Get Key Vault URI from Terraform output
AKV_URI=$(cd infra-deployment && terraform output -json useful_info | jq -r '.akv_uri')

# Configure customer-managed key (replace key name as needed)
oci db autonomous-database update \
  --autonomous-database-id $ADBS_OCID \
  --customer-contacts '[{"email":"admin@example.com"}]' \
  --kms-key-id "${AKV_URI}keys/exascale-encryption-rsa-4096"
```

⏱️ **Expected Time**: 10-30 minutes for re-encryption
📊 **Database Status**: Remains ONLINE and AVAILABLE during process

## 7. Validation and Testing

### 7.1 Comprehensive Validation Queries

## 8. Troubleshooting

### 8.1 DNS Resolution Issues

**Problem**: DNS resolves to public IP instead of private IP

**Diagnosis:**
```sql
SELECT utl_inaddr.get_host_address('exascale-kv-982.vault.azure.net') FROM dual;
-- If returns 104.x.x.x or similar public IP
```

**Solutions:**

1. **Verify OCI Private Zones:**
   - Check both zones exist: `privatelink.vaultcore.azure.net` AND `vault.azure.net`
   - Check A records point to correct Private Endpoint IP
   - Verify zones are in the correct Private View (matching VCN name)

2. **Check VCN Name:**
   ```sql
   -- Get VCN name from ADBS details in OCI Console
   -- Ensure Private View has EXACT same name
   ```

3. **Wait for DNS Propagation:**
   - Wait 5 minutes after creating/updating DNS records
   - Restart SQL Developer Web session

4. **Verify Private Endpoint:**
   ```bash
   az network private-endpoint show \
     --resource-group rg-oracle-prod-eastus \
     --name pe-kv-adbs \
     --query 'customDnsConfigs[0].ipAddresses[0]' \
     -o tsv
   ```

### 8.2 Network ACL Errors

**Error**: `ORA-29273: HTTP request failed`

**Cause**: Network ACL not configured or incorrect configuration

**Solution:**
```sql
-- Verify ACL exists
SELECT host FROM DBA_NETWORK_ACLS 
WHERE host LIKE '%vault.azure.net%';

-- If empty, add ACL (see Section 5.1)

-- If ACL exists but still fails, check exact hostname
-- Must match EXACTLY: exascale-kv-982.vault.azure.net
```

### 8.3 OAuth and Authentication Issues

**Error**: `DNS_PROBE_FINISHED_NXDOMAIN` when opening consent URL

**Cause**: URL contains "www." prefix

**Solution:**
```
Change: https://www.login.microsoftonline.com/...
To:     https://login.microsoftonline.com/...
```

---

**Error**: Consent URL redirects to wrong tenant

**Cause**: Using Subscription ID instead of Directory (Tenant) ID

**Solution:**
```sql
-- Get current tenant ID
SELECT param_value FROM CLOUD_INTEGRATIONS 
WHERE param_name = 'azure_tenantid';

-- If incorrect, disable and re-enable with correct ID
BEGIN
  DBMS_CLOUD_ADMIN.DISABLE_PRINCIPAL_AUTH(
    provider => 'AZURE',
    username => 'ADMIN');
END;
/

-- Wait 30 seconds, then re-enable with CORRECT Directory (Tenant) ID
BEGIN
  DBMS_CLOUD_ADMIN.ENABLE_PRINCIPAL_AUTH(
    provider => 'AZURE',
    params   => JSON_OBJECT('azure_tenantid' VALUE '<CORRECT-TENANT-ID>'));
END;
/
```

---

**Error**: "does not have keys list permission on key vault"

**Cause**: Using Azure RBAC roles instead of Access Policies

**Solution:**
1. Navigate to Key Vault → Access policies
2. Verify Access Policies are configured (not RBAC)
3. Add the ADBS Service Principal with required permissions:
   - Get, List, Wrap Key, Unwrap Key, Sign, Verify

### 8.4 Encryption Wallet Issues

**Problem**: Wallet shows UNDEFINED instead of CLOUD

**Diagnosis:**
```sql
SELECT wrl_type, wallet_type, status
FROM V$ENCRYPTION_WALLET;
-- If WALLET_TYPE = UNDEFINED
```

**Possible Causes:**
1. Customer-managed key not configured in OCI Console
2. OAuth not completed successfully
3. Key Vault permissions not set
4. Network connectivity issue

**Solution Checklist:**
- [ ] OAuth consent completed
- [ ] Access Policy configured
- [ ] Network ACL added
- [ ] DNS resolving correctly
- [ ] Customer-managed key configured in OCI

### 8.5 Firewall Blocking Traffic

**Problem**: DNS resolves correctly but connectivity fails

> **Note**: The Azure Firewall is deployed by Terraform as part of the infrastructure. If firewall rules need adjustment, you can modify `firewall.tf` / `firewall_policy.tf` and re-apply, or add rules manually.

**Diagnosis:**
```sql
-- DNS resolves to private IP (good)
SELECT utl_inaddr.get_host_address('exascale-kv-982.vault.azure.net') FROM dual;
-- Returns: 10.115.2.4

-- But connectivity test fails
-- Check if Azure Firewall is blocking
```

**Solution:**
If using Azure Firewall with UDR (User Defined Route):

```bash
# Add application rule to allow Key Vault access
az network firewall application-rule create \
  --collection-name allow-keyvault \
  --firewall-name <your-firewall-name> \
  --name allow-akv \
  --protocols https=443 \
  --resource-group <firewall-rg> \
  --source-addresses 10.115.1.0/24 \
  --target-fqdns "*.vault.azure.net" \
  --priority 200 \
  --action Allow
```

### 8.6 Key Rotation Rate Limit

**Error**: "You cannot switch to a different customer-managed key more than two times in a 24-hour period"

**Cause**: Oracle enforces 2 key changes per 24 hours

**Solution:**
- Wait 24 hours before next key change
- Plan key rotation tests across multiple days
- Use separate ADBS instances for testing different key types

### 8.7 Service Principal Cleanup

**Problem**: Multiple stale App Registrations in Azure AD

**Cause**: Each `ENABLE_PRINCIPAL_AUTH` creates a new Service Principal

**Solution:**
```sql
-- Before re-running ENABLE_PRINCIPAL_AUTH, always disable first
BEGIN
  DBMS_CLOUD_ADMIN.DISABLE_PRINCIPAL_AUTH(
    provider => 'AZURE',
    username => 'ADMIN');
END;
/

-- Clean up old Service Principals in Azure Portal:
-- Azure AD → App registrations → All applications
-- Delete old ADBS_APP_OCID1... registrations
```

## 9. Managed HSM Specific Steps

> **Partial automation available**: The orchestrator includes a `--only-configure-hsm` mode that automates HSM activation, role assignment, and key creation. However, OCI DNS and ADBS configuration remain manual.

### 9.0 Activate and Configure HSM (Automated)

If you deployed with `./deploy-exascale-demo.sh -hsm`, HSM configuration runs automatically after Terraform.

To configure an already-deployed HSM separately:

```bash
./deploy-exascale-demo.sh --only-configure-hsm
```

This will:
1. Activate the Managed HSM (using security domain certificates in `certs/`)
2. Assign **Managed HSM Crypto Officer** and **Crypto User** roles to the current user
3. Create encryption keys for ADBS testing
4. Display HSM connection information

### 9.1 Additional DNS Zones for Managed HSM (Manual)

In addition to standard Key Vault zones, add:

**Zone 3: privatelink.managedhsm.azure.net**
**Zone 4: managedhsm.azure.net**

```
Private View: VCN-multicloudnetworklink20250605145841
├── (Existing zones for standard Key Vault)
├── Private Zone: privatelink.managedhsm.azure.net
│   └── A Record: mhsm-exascale-142a.managedhsm.azure.net → 10.106.2.5
└── Private Zone: managedhsm.azure.net
    └── A Record: mhsm-exascale-142a.managedhsm.azure.net → 10.106.2.5
```

### 9.2 Network ACL for Managed HSM

```sql
-- Use wildcard for HSM endpoints
BEGIN
  DBMS_NETWORK_ACL_ADMIN.APPEND_HOST_ACE(
    host       => '*.managedhsm.azure.net',
    lower_port => null,
    upper_port => null,
    ace        => XS$ACE_TYPE(
      privilege_list => XS$NAME_LIST('resolve','http','connect'),
      principal_name => 'ADMIN',
      principal_type => XS_ACL.PTYPE_DB
    )
  );
END;
/
```

**Note**: Managed HSM requires additional privileges: `resolve`, `http`, `connect`

### 9.3 Managed HSM Local RBAC (Not Azure IAM)

**CRITICAL**: Azure IAM roles do NOT work for Managed HSM. Must use Local RBAC.

```bash
# Get Service Principal Object ID
APP_ID="<your-application-id>"
OBJECT_ID=$(az ad sp show --id $APP_ID --query id -o tsv)

# Assign Managed HSM Crypto Officer role (data plane)
az keyvault role assignment create \
  --hsm-name mhsm-exascale-142a \
  --role "Managed HSM Crypto Officer" \
  --assignee-object-id $OBJECT_ID \
  --assignee-principal-type ServicePrincipal \
  --scope "/"

# Verify assignment
az keyvault role assignment list \
  --hsm-name mhsm-exascale-142a \
  --query "[?principalId=='$OBJECT_ID']" \
  -o table
```
